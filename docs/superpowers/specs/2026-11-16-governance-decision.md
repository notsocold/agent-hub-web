## 1. 背景

2026-11-13 的[差异审计报告](../../handoff/2026-11-13-gap-audit-report.md)在“页面与接口接得上”的前提下，识别出 **30 项产品行为差异**（P1 7 项，其中 6 项集中在管理台），并指出根因分布：

- 后端契约缺口 **15 项（50%）**：v8 原型假设的**平台治理层**（RBAC 角色/权限、菜单、字典、认证策略、配额、数据保留、功能开关、危险操作）从未进入后端里程碑；
- 前端待办 **6 项（20%）**：轨迹抽屉、审批备注、智能体编辑等；
- 设计决策 **7 项（23.3%）** 与设计/产品变更 **2 项**：逐字续流、多实例 SSE、删除审批页、A2A 入站取消、画布、演示徽标、多语言、工作流步骤 6→5。

关键事实：

1. 后端 M0–M9（M3 取消）**已交付**，OpenAPI 78 路径 / 109 操作，前端 API 层 **0 幽灵调用**；后端不是“没做完”，而是原型里的治理域没有被立项。
2. 前端 M0–M9 **已完成**；M8 管理台**七页在位**，其中**角色/菜单/字典三页只读**，系统设置是**能力配置**形态；M9 工作流五类步骤已交付。
3. v8 原型把角色/菜单/字典/系统设置画成**可编辑的完整后台**；若继续用“v8 全量”表述，会把**目标形态**误当**交付事实**，评审与排期都会失真。
4. 需要一次治理层决策：**A 全量补齐 RBAC/平台运维**、**B 缩范围并正式标注目标形态**、**C 最小假 RBAC**。

## 2. 决策

**采用路径 B：缩范围 + 补真实数据 + 修前端交互。** 具体含义：

| 动作 | 内容 | 落地位置 |
|---|---|---|
| 缩范围 | 角色页保留只读矩阵 + 角色分布，文案标“v1 仅内置 user/admin；多角色为目标形态（未排期）”；菜单页保留路由只读镜像并说明“菜单变更需改代码”；字典页保留内置枚举只读并说明“字典项变更需发版” | `AdminRolesView` / `AdminMenusView` / `AdminDictionariesView`（本轮已完成） |
| 补只读平台信息 | 系统设置新增两个**只读**分区：`平台信息`（`/system/info` 的 version/build/environment/models/embedding）与`能力开关`（`capabilities` 与 `limits`）；不提供认证策略/配额/数据保留/危险操作的**可写假控件** | `AdminSettingsView` + 只读面板组件（本轮已完成） |
| 修前端交互 | 运行轨迹抽屉、审批备注、智能体编辑、工作流候选/停用提示、系统模板守卫、管理台搜索、用户导出等前端可收口项 | 见[整改方案](../plans/2026-11-13-gap-remediation.md) WP2/WP3 |
| 补真实数据（后端增量） | 审计 IP/结果、概览运行量、用户会话数、工作流运行统计、偏好同步、知识库分类/重建别名等，需后端契约；本轮**只读核对**，按后续排期实施 | 见[整改方案](../plans/2026-11-13-gap-remediation.md) WP1/WP4 |
| 正式接受 | D6/D7/D8/S1/S3/A2/W1/W3/M10/G1，以及 M3 的邀请部分、M9 的通知部分，逐条写入接受清单并给出重开条件 | [接受清单](../../handoff/2026-11-13-accepted-deviations.md) |
| 统一口径 | “完成”固定为**契约先行 / 前端完成 / 联调完成**三档；v8 统一表述为“**七页在位；角色/菜单/字典只读；系统设置为能力配置 + 平台信息（只读）形态**” | [路线图](../../roadmap.md) §0、[页面规划](../../pages.md) §8.1、[README](../../../README.md) |

> **B 不是“不做”**：不可编辑项被正式标注为目标形态；可得的真实数据与前端交互照常补齐；不可得的后端能力不伪造。

## 3. 备选方案

| 选项 | 范围 | 后端 | 前端 | 周期/成本 | 风险 | 适用条件 |
|---|---|---|---|---|---|---|
| **A 全量治理** | RBAC 角色/权限、菜单、字典、平台设置（认证/配额/保留/开关/危险操作） | 建 4–6 张表 + 15–20 个端点 + 权限中间件 + 迁移 | 3 页可编辑 + 系统设置 7 分区 | 4–6 周；后端约 20–25 人日 + 前端 8–10 人日 | **高**：RBAC 影响所有路由；迁移不可轻回滚 | 近期确有多角色/多租户/合规审计要求 |
| **B 缩范围（本决策）** | 保留 2 角色；角色/菜单/字典只读；系统设置补只读平台信息/能力开关 | 只做低成本审计/统计字段（本轮只读核对） | 3 页标注目标形态；系统设置加只读面板；修可收口交互 | 治理层收口 1–2 人日；叠加 WP1/WP4 全量约 27.5 人日 | **低**：不动权限模型、可逆 | 内部平台，user/admin 足够 |
| **C 最小 RBAC** | 只加 roles 表做标签，不做权限判定 | 小 | 小 | 1 周 | **中高**：假 RBAC，误导使用方 | 不建议 |

**否决 A 的理由**：当前缺乏多角色/多租户/合规审计需求，A 的收益低于 20–25 人日的后端治理成本，且 RBAC 迁移会影响全部路由，回滚代价高；若未来需求成立，应以独立 M10 立项（见 §6）。

**否决 C 的理由**：只做“角色标签”而没有权限判定，会制造“看着能配、实际不生效”的假能力，比只读更危险。

## 4. 决策理由

1. **产品阶段匹配**：这是面向终端用户的内部对话平台，当前 `user/admin` 两角色足以支撑权限边界；没有多角色/多租户/合规审计的明确需求。
2. **投入产出比**：A 路径的治理工程（4–6 表、15–20 端点、权限中间件）远超当前收益；B 路径把有限投入放在**真实数据可信度**（审计 IP/结果、运行量、会话数）与**前端体验**（轨迹、审批备注、编辑能力）上。
3. **风险可逆**：B 不改权限模型、不新增 RBAC 表，后续转 A 不会产生“半成品角色表”的迁移债务。
4. **口径诚实**：把不可编辑项正式标注为目标形态，评审、验收与后来者不会再误判进度；这直接关闭审计报告 §0.2 第 5 条“文档状态滞后于实现”。
5. **已有证据支持“后端已交付”**：后端 M0–M9 已交付，`smoke:m8` **69/69**、`smoke:m9` 67 项真实后端通过（[M8 留档](../../handoff/2026-11-16-m8-smoke.md)）；前端最终门禁 561 单测 / 88 files、E2E 44 passed + 1 skipped（2026-11-16，[整改报告](../../handoff/2026-11-16-gap-remediation-report.md)），问题集中在治理域范围而非缺陷。

## 5. 影响

### 5.1 产品与页面

- **管理台**：七页在位成为正式口径；角色/菜单/字典三页只读并被接受；系统设置为**能力配置 + 平台信息（只读）**形态；认证策略/配额/数据保留/功能开关/危险操作标注“目标形态、未排期”，不提供可写假控件。
- **设置页**：语言只读、A2A 分区移除等进入接受清单；语言项补充“多语言未启用（未排期）”说明。
- **工作流**：五类步骤为最终形态，技能/MCP 由 `tool` 步骤承载；无拖拽画布。

### 5.2 文档与验收

- 根 README、路线图、页面规划、原型索引、交接包统一到 2026-11-16 口径；Doc1–Doc5 修正清单见[文档修订记录](../../handoff/2026-11-16-doc-sync.md)。
- “完成”改为三档：**契约先行**（类型/API/mock/OpenAPI 冻结）→ **前端完成**（页面/交互/单测/E2E(mock)）→ **联调完成**（真实后端 smoke + 一条真实 HTTP/浏览器证据 + 文档勾选）；mock 通过不得写成“已联调”。
- 接受项不再按 bug 跟踪；重开条件满足时按 §6 重新评估。

### 5.3 风险与缓解

| 风险 | 触发 | 缓解 |
|---|---|---|
| 使用方仍按“v8 全量”预期提需求 | 评审/交付沟通 | 文档与页面统一“七页在位、三页只读、系统设置为能力配置 + 平台信息（只读）”；页面顶部 READ-ONLY 标签与原因说明 |
| 未来转 A 时返工 | 多角色需求出现 | B 不预埋半成品角色表；A 以 M10 独立 spec 重新设计（见 §6） |
| 只读被误解为“做不了” | 用户反馈 | 接受清单写明重开条件与 A 路径触发条件；路线图保留候选 M10+ |
| 文档再次漂移 | 后续里程碑 | 每次里程碑收口必须同步 README/roadmap/pages，并以 `doc-sync` 方式留痕 |

## 6. 升级到 A 路径的触发条件

出现以下**任一**情况，应在 2027-02-16 复核前提前重开治理决策，并以“**M10 平台治理**”独立立项（不复用本轮 B 的临时结构）：

1. **多角色需求**：需要 3 个及以上角色，或需要按角色做细粒度权限判定（菜单/操作/数据范围）；
2. **多租户**：需要组织/租户隔离、跨租户管理与计费；
3. **合规审计要求**：等保、SOC 2、ISO 27001 等要求权限分离、操作留痕、审批链可审计；
4. **平台自运维需求**：需要在管理台自助配置认证策略、配额、数据保留、功能开关或危险操作；
5. **治理层缺陷反复出现**：只读方案被使用方持续投诉且无法用文档解释收口。

A 路径预估：后端 20–25 人日（4–6 张表、15–20 个端点、权限中间件、迁移）、前端 8–10 人日（3 页可编辑 + 系统设置 7 分区），需独立 spec + 独立计划 + 迁移回滚方案。

## 7. 有效期与复核

- **有效期至 2027-02-16**（自 2026-11-16 起 3 个月）；到期或触发 §6 条件时复核。
- 复核检查项：
  - 是否出现多角色/多租户/合规审计需求（§6）；
  - 只读页面是否引发实际使用阻塞；
  - 后端 WP1/WP4 增量（M1/M2/M7/S2/K1/K2/W2）是否排期并落地；
  - 文档口径是否与实现再次漂移。
- 若复核无触发条件：可延续 B 并再设 3 个月复核期；若触发：转入 M10 立项评估。
