## 2. 逐项说明

### AD-D6 断线窗口 `message.delta` 不补齐

- **现象**：SSE 断开期间未落库的增量文本不会补发；重连只回放已落库事件，最终内容通过终态 `refreshHistory()` 对齐。
- **为什么接受**：后端 M7 已明确“非目标：`message.delta` 不落库”，逐字续流需要把所有 delta 持久化，存储与时序成本高；终态刷新保证**最终内容正确**，断线只影响过程可见性。
- **影响**：断线期间用户看不到逐字生成过程，恢复后消息完整；不影响最终结果、run 记录与审计查询。P2，非主链路阻断。
- **重开条件**（任一）：① 产品要求“断线期间逐字无丢失”；② 后端将 `message.delta` 落库或提供补洞端点；③ 出现合规要求完整留存流式过程。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/pages.md` §3“断线”、`docs/roadmap.md` M6/M7 说明。

### AD-D7 多实例 SSE 不支持

- **现象**：SSE 连接与 run 状态绑定单实例；多副本部署时重连可能落到无状态实例，续流失败。
- **为什么接受**：当前为单实例部署，扩容尚未发生；粘性会话或 Redis 事件总线需要基础设施投入，属于“扩容前置条件”而非当前缺陷。
- **影响**：横向扩展前必须先完成 SSE 方案；单实例下不影响使用。P2。
- **重开条件**（任一）：① 计划多副本/水平扩容；② 单实例吞吐不足或 SLA 要求高可用；③ 出现跨实例运行续流的真实故障。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/roadmap.md` §6“多实例 SSE”行。

### AD-D8 独立审批页 `/approvals` 删除

- **现象**：`/approvals` 路由、页面与命令面板项已删除；审批只在对话内卡片完成；`GET /approvals` 仅用于断线补卡与兜底。
- **为什么接受**：v7 原型本身就是对话内审批；PA-1（2026-11-11）正式决策删除独立页，上下文更完整，避免跨页丢失运行信息。
- **影响**：审批入口单一，深链只能定位到对话内的卡；无管理员全量审批视图（后端也无该能力）。P3。
- **重开条件**（任一）：① 出现跨会话集中审批/审批工作台的明确需求；② 通知或移动端场景要求独立审批入口；③ 审批量增长导致对话内定位成本不可接受。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/pages.md` §7.1、[像素级对齐报告](2026-11-12-pixel-alignment-report.md) §2。

### AD-S1 语言切换只读

- **现象**：设置页语言下拉为禁用状态，仅展示「简体中文（zh-CN）」；原型有简中/English 切换。
- **为什么接受**：完整 i18n 未排期；只做半套切换会给用户错误预期；当前产品面向中文用户，英文需求未出现。
- **影响**：非中文用户无法使用；语言项仍展示（禁用 + 说明），不伪造可切换。P2。
- **重开条件**（任一）：① 出现英文用户/海外部署需求；② 产品排期 i18n（词条抽取、日期/数字格式、E2E）；③ 多语言成为验收硬指标。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/pages.md` §8 界面分区。

### AD-S3 A2A 设置分区移除

- **现象**：设置页的「A2A 端点」分区整块移除，没有入站端点/鉴权配置入口。
- **为什么接受**：M3「A2A 入站」因 2026-11-10 需求变更取消，服务仅做出站 A2A Client；入站能力没有实现，也就不应有配置入口。
- **影响**：出站智能体统一在「智能体」页注册与管理；设置页面更短、更聚焦个人能力。P3。
- **重开条件**（任一）：① 恢复 A2A 入站需求；② 需要发布 Agent Card / JSON-RPC 入站端点 / 入站鉴权。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/roadmap.md` M3 取消说明、§6“A2A 入站”决策记录。

### AD-A2 全局 Agent 的 `headers` 不可编辑

- **现象**：管理台全局 Agent 卡片不提供 `headers` 编辑 UI；后端响应不回显明文 headers。
- **为什么接受**：安全取舍——回显明文凭据有泄露风险，前端在无脱敏回显时强行编辑可能整体覆盖既有配置；后端当前不支持“脱敏回显 + 留空不修改”的契约。
- **影响**：管理员修改 headers 需通过后端配置渠道；页面只提供可编辑白名单字段。P2。
- **重开条件**（任一）：① 后端提供脱敏 headers 回显并明确“留空=不修改、填写=整体覆盖”的契约；② 出现必须在前端完成 headers 运维的流程；③ 安全评审通过回显方案。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/roadmap.md` M8 完成情况“已知限制”。

### AD-W1 工作流步骤模型 6 类 → 5 类

- **现象**：原型可把“技能”“MCP”作为独立步骤；后端 M9 只提供五类步骤（`knowledge_search` / `tool` / `a2a` / `approval` / `answer`），技能与 MCP 通过 `tool` 步骤或对话上下文承载。
- **为什么接受**：M9 的产品/技术决策；统一 `tool` 抽象减少步骤类型与执行分支，技能/MCP 仍可被编排（在 `tool` 步骤中选择或于对话上下文启用）。
- **影响**：原型中的“技能步骤”“MCP 步骤”无法逐项映射；需要在页面与文档解释“技能/MCP 由工具步骤承载”。P2。
- **重开条件**（任一）：① 产品确认需要独立的技能/MCP 步骤语义；② `tool` 步骤无法表达其参数、审批或输出；③ 后端 workflow schema 变更。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/pages.md` §8.2、`docs/roadmap.md` M9“五类步骤”。

### AD-W3 无拖拽画布

- **现象**：工作流编辑器为线性步骤列表（增删/上移下移），没有原型级拖拽画布。
- **为什么接受**：M9 明确定位“轻量步骤模板”，不做 BPMN/DAG 执行器；拖拽画布的交互、无障碍与移动端成本高，线性列表已满足有序步骤编排。
- **影响**：复杂编排的可视化能力弱；步骤较多时编辑效率一般。P3。
- **重开条件**（任一）：① 出现多分支/DAG/并行编排需求；② 节点数经常超过 12 步且用户反馈效率不足；③ 画布作为 F3 正式立项并通过设计评审。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/pages.md` §8.2、[像素级对齐报告](2026-11-12-pixel-alignment-report.md) §4。

### AD-M10 「原型演示」徽标等装饰未实现

- **现象**：管理台的「原型演示」徽标、顶栏装饰性元素未实现。
- **为什么接受**：非产品功能；把演示态带入生产会造成误导；像素级对齐报告 §4.3 已声明为有意偏离。
- **影响**：视觉与原型存在细微差异，不影响功能与信息架构。P3。
- **重开条件**（任一）：① 需要对外演示/培训环境并明确要求还原；② 产品提出品牌装饰需求。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：[像素级对齐报告](2026-11-12-pixel-alignment-report.md) §4.3。

### AD-G1 A2A 入站能力取消

- **现象**：不发布 Agent Card、不暴露 `.well-known` / JSON-RPC 入站端点、不做入站鉴权、不做 `contextId ↔ conversationId` 映射、不实现入站任务与会话。
- **为什么接受**：2026-11-10 需求变更——本服务只做出站 A2A Client；入站没有明确业务场景，保留编号空位避免与后端里程碑错位。
- **影响**：本服务不能被其他 A2A 客户端调用；M3 编号保留空位；设置页 A2A 分区随之移除（见 AD-S3）。P3。
- **重开条件**（任一）：① 出现被其他 Agent 调用的需求；② 需要作为 A2A Server 参与生态；③ 入站鉴权与多租户方案明确。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **依据**：`docs/roadmap.md` M3 取消说明、§6 决策记录。

### AD-M3i 用户页「邀请用户」部分

- **现象**：管理台用户页无「邀请用户」入口；本轮补齐的是**导出 CSV**（当前筛选/当前页），邀请仍不提供。
- **为什么接受**：没有邮件与邀请 token 基础设施；邀请涉及邮件发送、token 过期、防滥用与审计，成本高于当前价值；若需要，建议另立“管理员创建用户”端点（临时密码，2–3 人日）。
- **影响**：新用户需管理员手动创建或自行注册；无批量邀请能力。P2。
- **重开条件**（任一）：① 出现批量开号/团队开通需求；② 邮件服务接入；③ 后端提供管理员创建用户或邀请端点。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **备注**：M3 的**导出部分**不属于接受项——本轮由前端 CSV 导出实现（2026-11-16）。

### AD-M9n 管理台顶栏「通知铃铛」部分

- **现象**：管理台顶栏无通知铃铛/通知中心；本轮补齐的是**全局搜索**（命令面板：管理台路由、用户、审计动作）。
- **为什么接受**：没有通知中心基础设施（通知存储、已读态、订阅、推送）；通知属于独立产品能力，不是当前核心流程。
- **影响**：管理员需主动查看概览/审计/运行状态；无实时告警推送。P2。
- **重开条件**（任一）：① 需要审批/失败运行/系统告警的实时触达；② 后端提供通知端点；③ 接入邮件或 IM 通知。
- **决策日期**：2026-11-13（B 路径）/ 2026-11-16（本轮确认）
- **备注**：M9 的**搜索部分**不属于接受项——本轮由前端命令面板实现（2026-11-16）。
