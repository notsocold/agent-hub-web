2026-11-16 在 agent-hub-web + agent-hub 后端完成三项修复（本地未提交）：

1. 会话标题不生成根因：前端「新建会话」预创建会话时默认标题是「新会话」，后端 app/modules/chat/service.py 只在 title == "新对话" 或 is_new 时用首条消息生成标题，导致预创建会话标题永远停在「新会话」。
   修复：前端 src/api/conversations.ts 与 mock（routers/db/stream）默认标题统一为「新对话」；后端条件改为 `if is_new or conversation.title in {"新对话", "新会话"}`，兼容旧数据且不覆盖用户手动改名的会话。
   真实后端验证：创建 title=新会话 → 发首条消息 → 标题变为消息内容（通过）。

2. 重开会话后右侧运行轨迹侧栏清空：chat.loadConversation 重置 state.process=[]，只有 adoptRun（活 run 恢复）会 replayPersistedEvents，历史会话不回放。
   修复：loadConversation 对 conversation.last_run 调用 replayPersistedEvents(lastRun.id, 0)，回放后按 last_run 权威状态收尾 streaming/runStatus；chat-reducer 的 message.created 增加按 message.id 去重（旧消息 client_message_id 为 null 时避免回放重复插入）。
   数据源已验证：GET /runs/{id}/events 返回的 tool.start/tool.result/a2a.task 等事件带 event 字段，可被前端白名单回放。

3. 侧栏列表刷新丢分页：ChatView 在流结束时调用 conversations.load() 会 reset 回第一页。
   修复：新增 conversations.refresh()（按已加载条数翻页刷新、保留本地空会话），ChatView 流结束改调 refresh()。

测试：前端 477 单测全绿（新增 chat-replay 历史回放用例、conversations refresh 用例）；type-check/lint 通过；后端 tests/integration/test_chat.py + test_conversations.py 13 passed（新增 2 个标题用例，使用独立测试库 agent_hub_test，已按 alembic 迁移到最新 schema）。

审批仍非代码缺陷：仅 requires_approval=true 的 MCP 工具、requires_approval=true 的 A2A 目标 Agent、或含审批步的 workflow 会触发审批；当前库 MCP/工作流为 0、20 个远程 Agent 全 false、approvals 表 0 条。演示需先在管理台给目标 Agent 打开 requires_approval 或配置 MCP/工作流。
