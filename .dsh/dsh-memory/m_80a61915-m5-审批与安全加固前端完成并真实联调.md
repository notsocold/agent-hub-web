M5（审批与安全加固）前端交付要点：
1) 审批事件按后端真实契约重写：approval.required → run.interrupted（非终态，SSE 保持，payload.approvals 为本轮 pending ids）→ 决定 → run.resumed → delta → message.done；支持多审批逐卡处理（中间决定 resumed=false + "本轮还有其他审批待处理" 属正常提示，不是失败）、超时（canceled + reason=approval_timeout → 卡置不可操作）、409 approval_expired / approval_already_decided（后者重拉 GET /approvals/{id} 用服务端结论覆盖卡片）、断线轮询对账，并兼容旧后端 finish_reason=interrupted。
2) 关键教训（独立审查发现的 Critical）：真实模式的 SSE 事件白名单与 mock 是两层，mock 与单测绕过白名单，导致 run.interrupted / run.resumed 在真实模式被丢弃。修复方式是补白名单、导出事件清单并用 ChatEventName 类型约束、补事件分发测试。今后新增聊天事件必须同步改真实 SSE 白名单。
3) approval.required 事件字段少于 ApprovalOut（缺 tool_display_name/executor/target/side_effect/payload_preview），前端在 run.interrupted 后拉审批列表补卡。
4) 其他：审批卡实时倒计时与敏感 payload 遮罩；新增 /approvals 审批中心（5 键 stats、待处理/历史 Tab、conversation_id/run_id 过滤）；设置页新增「安全与审计」（普通用户 /audit-logs，管理员 /admin/audit-logs 与 /admin/secrets，503 secret_store_unavailable 与 403 分开提示，明文永不回显）；聊天与登录 429 倒计时、Markdown 外链域名确认、401 跳登录。用户/RBAC/菜单/字典仍未做，留在 X2。
5) 收尾状态：本地提交 6922fa6 未推送，工作区只剩 .dsh/sessions 会话快照未跟踪未提交；dev@example.com 仍为 admin，如需回收执行后端的 scripts/grant_admin.py dev@example.com --revoke。
