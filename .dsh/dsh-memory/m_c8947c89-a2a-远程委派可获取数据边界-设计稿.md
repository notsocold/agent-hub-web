A2A 仍为设计稿（agent-hub 仓库 app/modules/a2a/ 只有 .gitkeep），当前无真实远程数据。

调用链路：主智能体 → send_message(agent, task, context?) → A2AClient → A2A message/send 或 message/stream → 远程 Agent。send_message 才是与远程智能体通信的唯一入口。

用户结论：后端设计稿里按每个远程 Agent 的每个 skill 生成的 agent_<slug>__<skill_id> 包装工具不是 A2A 协议要求，不需要——它不传 skill_id，a2a_tasks 也没有 skill_id 字段，前端与任务记录都无法验证远程内部实际用了哪个 skill。统一暴露一个 send_message 工具即可，per-skill wrapper 可以完全去掉；即使后端为模型路由保留 wrapper，也不应把 wrapper 名暴露到用户界面。

界面侧已按此模型清理：对话页远程委派行只显示远程 Agent / 任务目的 / 结果摘要 / 状态与 task id / 查看流、查看结果；运行轨迹与任务详情「工具」显示 send_message，A2A 子标题改用 task id；工作流 A2A 步骤只选远程 Agent（data-analyst、editorial-reviewer、code-assistant）而非「Agent + skill」组合；Agent Card 页仍展示 skills（verify_numbers / review_copy / review_code），但语义是能力声明而非本次调用的工具。

流式与非流式仍由 Agent Card capabilities.streaming 决定；skills 仅用于能力发现。

待同步：后端文档 docs/a2a.md §5.2 仍写着「每个 Agent 的每个技能生成一个工具 agent_<slug>__<skill_id>」，若后端确定改为统一 send_message，该段需一并改写并移除按 skill 裁剪工具数量的描述。
